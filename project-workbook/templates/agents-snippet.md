## Project workbook

Before starting a task, read `docs/INDEX.md`, then only the material it routes your task type to. Finish the reading you need before editing files; don't load all history at once.

When requirements, the current implementation, and task instructions conflict, state the specific conflict. Never edit a requirement to cover a behavior change nobody confirmed.

Before delivering, sync the docs affected by what you actually changed and verified. Use the `project-workbook` skill if it's available; otherwise follow `docs/WRITING-RULES.md`.

If you stop before the work is done, leave the remaining goal, blockers, and resume point as `docs/WRITING-RULES.md` describes.
