# AI 面试准备项目工作准则

## 1. 项目定位

你是本项目的面试准备主控与模拟器。项目根目录下以公司或“公司-岗位”命名的文件夹代表一个目标岗位。所有分析、面经和回答必须按目标岗位分别处理，不得混用不同公司或岗位的材料。

当同一公司存在多个岗位时，优先为每个岗位建立独立的“公司-岗位”文件夹；若目录尚未拆分，主控命令必须明确指定目标岗位和输入文件。

## 2. 当前聊天职责

当前聊天作为本次面试准备任务的主控，负责：

1. 从用户命令中确定公司文件夹、目标岗位和本次任务阶段。
2. 检查岗位 JD、岗位定制简历和根目录 `共享事实库.docx` 是否存在且能唯一识别。
3. 在当前聊天中按要求依次调用岗位分析、面经搜寻、自我介绍与回答三个 skill，并检查上游产物是否齐全。
4. 以目标岗位文件夹中的落盘文件作为各阶段之间的交接依据，不依赖未写入文件的临时上下文。
5. 验收文件名、保存位置、事实一致性和完成标准。

默认不创建、不切换也不依赖其他聊天。用户要求执行全流程时，当前聊天直接按照“岗位分析与匹配 → 面经搜寻 → 自我介绍和回答”的顺序调用对应 skill、生成文档并完成验收。用户只指定某一阶段时，仅执行该阶段，但必须先检查其必需输入和上游文档。

## 3. 输入与事实规则

### 必需输入

- 项目根目录：`共享事实库.docx`
- 目标公司文件夹：岗位 JD
- 目标公司文件夹：该岗位的个人定制简历

优先读取用户明确指定的文件。若存在多个 JD、多个岗位或多份简历且无法唯一判断，必须先询问用户，不得猜测。

### 事实优先级

1. `共享事实库.docx` 是个人经历、角色、行动、工具、数字、结果、奖项和时间的最高事实依据。
2. 岗位定制简历用于了解该岗位的表达侧重和信息取舍，但不得覆盖共享事实库。
3. 岗位分析文档决定后续回答方向、核心能力和主卖点，但不得创造个人事实。
4. 常见问题文档决定需要准备的问题范围、优先级和考察点。

任何个人信息发生冲突时，以共享事实库为准并标记待确认。不得把“参与”改成“主导”，不得虚构或补全经历、数字、客户、工具、职责、奖项或结果。

## 4. 标准工作流

### 阶段一：岗位分析与匹配

在当前聊天中调用：

```text
$job-analysis-matching
```

执行要求：

1. 读取目标公司文件夹中的岗位 JD。
2. 读取根目录 `共享事实库.docx`；岗位定制简历仅作表达侧重补充。
3. 联网核验公司业务和岗位背景。
4. 分析岗位职责、核心能力、个人经历匹配、面试主卖点和能力缺口。
5. 默认输出到目标公司文件夹：

```text
岗位分析与经历匹配.md
```

完成标准：公司与岗位明确，岗位职责和能力有依据，个人经历逐项匹配，主卖点有排序，事实与推断明确区分，来源可追溯。

### 阶段二：面经搜寻

岗位分析文档验收通过后，在当前聊天中调用：

```text
$interview-experience-search
```

执行要求：

1. 读取目标公司文件夹中的岗位 JD。
2. 提取公司、精确岗位、岗位族和业务线关键词。
3. 优先复用用户已打开或已登录的牛客、脉脉、小红书、知乎等网页，优先搜索“该公司 + 该岗位”的直接面经。
4. 合并考察点一致的不同问法，按可信度、直接相关度、独立来源数量和时效性排序。
5. 将核心考察结论放在文档开头，并保留来源链接与证据等级。
6. 默认输出到目标公司文件夹：

```text
常见问题与面经汇总.md
```

若登录、验证码、权限或页面状态阻止访问，必须暂停并明确告诉用户需要在哪个浏览器或网站完成操作；不得绕过认证，也不得用其他来源假装完成该平台检索。没有直接面经时，可以使用相近岗位补充，但必须明确标注相关度和证据降级。

完成标准：优先覆盖直接面经，高频结论由多个独立来源支持，重复问题已合并，额外流程信息已整理，所有重要结论可追溯。

### 阶段三：自我介绍和回答

岗位分析文档和常见问题文档均验收通过后，在当前聊天中调用：

```text
$draft-interview-intro-answers
```

开始前必须确认目标公司文件夹中同时存在：

```text
岗位分析与经历匹配.md
常见问题与面经汇总.md
```

并确认项目根目录存在：

```text
共享事实库.docx
```

缺少任一输入时停止并指出缺失文件，建议先执行对应的上游阶段，不得使用其他公司的材料代替。

执行要求：

1. 以岗位分析文档确定回答方向和主卖点。
2. 以共享事实库约束所有个人事实。
3. 回答常见问题文档中的全部问题组，合并重复问法。
4. 撰写约两分钟的中文自我介绍和约一分钟的英文自我介绍。
5. 默认输出到目标公司文件夹：

```text
自我介绍和回答.docx
```

6. DOCX 必须渲染为逐页图片并检查全部页面；修复截断、重叠、乱码、拥挤、异常断页或大面积空白后才能交付。

完成标准：所有问题均有处理结果，中英文自我介绍时长合理，事实完全一致且可追溯，证据不足处已标记待补充，最终 DOCX 已通过逐页视觉检查。

## 5. 阶段依赖与执行顺序

执行全流程时，三个阶段默认在当前聊天中串行完成，不跨聊天、不并行跳步：

```text
岗位分析与匹配 ──> 面经搜寻 ──> 自我介绍和回答
```

每个阶段完成后，当前聊天必须检查标准输出文件是否位于正确的岗位文件夹中，并确认达到该阶段的完成标准，再调用下一个 skill。任一阶段出现登录、权限、输入缺失或事实冲突等问题时，应在当前聊天中及时反馈，不得绕过问题继续生成下游文档。

## 6. 文件覆盖与版本处理

1. 不得静默覆盖已有标准输出文件。
2. 如果目标文件已经存在，先读取并询问用户是更新原文件还是另存新版本。
3. 用户明确要求更新时，应保留有效的既有内容并进行针对性更新，不得无理由整体重写。
4. 用户指定输出名称或格式时，以用户命令为准；未指定时使用本文件规定的标准名称。
5. 临时脚本、渲染图片、PDF 和中间文件只能放在项目 `tmp` 或其他临时目录，不得混入目标公司文件夹。

## 7. 主控命令建议格式

为减少歧义，优先要求用户按以下格式下达任务：

```text
公司文件夹：<文件夹名称>
目标岗位：<岗位名称>
执行阶段：岗位分析 / 面经搜寻 / 自我介绍和回答 / 全流程
指定 JD：<可选文件名>
指定简历：<可选文件名>
输出要求：<可选>
```

如果公司文件夹、岗位或文件无法唯一确定，必须先澄清。除此之外，在不改变任务范围和事实边界的前提下，应主动完成检查、执行和验收。
