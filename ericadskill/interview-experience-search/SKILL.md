# 面经搜寻

## 目标

以目标岗位 JD 为范围锚点，系统搜集并综合公开面经。优先回答“该公司该岗位实际重点考什么”，保留来源和不确定性，不把单篇帖子或转述包装成高频规律。

## 工作流

### 1. 确定公司与岗位

1. 从主控聊天命令中取得公司文件夹、岗位名称，以及用户指定的时间范围、网站、文件格式或文件名。
2. 如果公司文件夹或目标岗位不能唯一确定，停止并向用户确认，不根据相似名称猜测。
3. 优先读取用户点名的 JD；否则在公司文件夹中查找文件名包含 `JD`、`岗位` 或岗位名称的 DOCX、PDF、Markdown 或文本文件。
4. 完整读取 JD，提取：
   - 公司标准名称、常用简称和品牌名；
   - 岗位标准名称、岗位族和常见同义名称；
   - 业务线、职能方向、关键职责和能力关键词。
5. 若多个 JD 对应不同岗位且无法唯一判断，向用户确认。

### 2. 生成检索词

由“公司词 × 岗位词 × 招聘/面试词”组合检索，不局限于两个字面关键词。

- 公司词：公司全称、简称、品牌名、业务线名称。
- 岗位词：JD 原名、去除届次或地点后的名称、岗位族、常见近义岗位名。
- 招聘/面试词：`秋招`、`校招`、`应届`、`面经`、`一面`、`二面`、`终面`、`HR面`、`群面`、`AI面`、`笔试`。

按以下顺序扩展：

1. 公司 + 精确岗位 + 面经；
2. 公司 + 精确岗位 + 秋招/校招/具体面试轮次；
3. 公司 + 同岗位族或同业务线岗位；
4. 同类公司 + 同岗位，仅用于补足通用岗位问题。

不得让低相关扩展结果淹没“该公司该岗位”的直接面经。

### 3. 使用已打开的网页搜寻

1. 任务依赖用户已打开或已登录的网页时，使用对应的浏览器控制 skill，并遵守其浏览器选择、连接、认证和交互规则。
2. 优先复用用户当前已登录的牛客、脉脉、小红书、知乎页面，在各平台站内搜索并打开相关结果。
3. 对每个平台执行多组检索词，继续翻阅足够结果以判断是否出现新问题或新考察点；不要只读取首条结果。
4. 若站内搜索较弱，可使用公开搜索引擎的 `site:` 查询定位页面，再在允许访问的页面内核实内容。
5. 如果登录、验证码、权限或页面状态阻止访问，明确告诉用户需要在哪个浏览器或网站完成操作，不绕过认证或改用其他来源假装完成该平台检索。
6. 不读取账号密码、Cookie、私信或非任务所需的个人信息；不进行高频批量抓取，不绕过网站访问限制。
7. 可补充公司官网、招聘官网及其他公开社区信息，但必须标明来源类型。

### 4. 建立来源记录

对每条有效面经记录：

- 平台、标题或可识别描述、链接；
- 发布日期或可见时间；
- 公司、岗位、招聘届次或年份；
- 面试轮次和原帖是否为本人经历；
- 提及的问题、流程、考察点及其他信息；
- 与目标岗位的关系和可信度等级。

不得大段复制帖子原文。用自己的语言归纳，仅在必要时保留很短的关键措辞。

### 5. 评估相关度与可信度

使用以下证据层级：

- **A 级**：同公司、同岗位或高度一致岗位的本人直接面经，轮次和过程具体。
- **B 级**：同公司相近岗位，或同岗位不同届次的直接面经。
- **C 级**：其他公司同类型岗位的直接面经，仅支持岗位通用问题。
- **D 级**：二手转述、汇总帖或缺少上下文的信息，只作线索。

在同一等级内，综合直接相关度、来源完整性、独立来源数量和时效性排序。不要仅凭点赞、热度或平台知名度判断真实性。

只有至少两个相互独立的来源支持时，才称为“多次出现”或“高频”。单一来源只写“曾出现”。无法确认多个帖子是否互相转载时，不按独立来源累计。

### 6. 提炼考察点并合并问题

1. 先综合全部 A、B 级面经，提炼该公司该岗位最重要的考察点；证据不足时明确降低结论强度。
2. 将每个问题映射到一个主要考察点，例如岗位动机、业务理解、数据分析、项目推进、用户洞察、跨部门协作、压力与复盘。
3. 对语义相同、考察目标一致的不同问法进行合并，保留 2–4 个代表性问法并标注“同一考察点的不同问法”。
4. 不要仅因关键词不同就拆成重复问题；也不要把考察目标不同的问题强行合并。
5. 为每组问题记录出现于哪些来源层级、独立来源数、常见面试轮次及相关岗位范围。
6. 按可信度和直接相关度排序；当证据相近时，再按出现频次和时间新旧排序。

### 7. 收集其他有价值信息

不限于问题清单。遇到以下信息时单独整理，但不要把推测写成事实：

- 面试流程、轮次数量、群面/笔试/AI 面形式；
- 各轮侧重点、追问方式和案例题形式；
- 时间节奏、候选人背景偏好或岗位实际工作信息；
- 面试官特别关注、明显淘汰风险和准备建议；
- 不同届次、地区或业务线之间的差异；
- 与 JD 表述不完全一致但多篇面经共同反映的实际要求。

### 8. 判断何时停止检索

覆盖用户指定的平台和主要检索词后，再检查新增结果是否仍产生新的问题组或考察点。连续多组高相关结果不再产生实质新增信息时，可以停止。不要为了数量收录大量低相关或重复内容。

## 输出规范

若用户未指定格式，在目标公司文件夹中生成 `常见问题与面经汇总.md`。若同名文件已存在且用户没有明确要求覆盖，先读取现有文件并询问是更新还是另存；不得静默覆盖。若用户指定 DOCX，则调用文档能力生成并完成渲染和视觉检查。

文档按以下结构输出：

1. **核心结论：最重要的考察点**  
   结论前置，按重要性列出考察点、依据、置信度及对应面试轮次。
2. **检索范围与证据概况**  
   公司、岗位、JD 文件、平台、检索日期、时间范围、A/B/C/D 级来源数量和检索限制。
3. **直接面经综合分析**  
   优先总结 A、B 级材料反映的流程、重点和差异。
4. **常见问题清单**  
   每组包含：合并后的主问题、同考察点不同问法、考察意图、来源等级、独立来源数、常见轮次、直接相关度和准备提示。
5. **其他有价值信息**  
   流程、形式、节奏、岗位实际要求、风险或额外准备建议。
6. **低置信度信息与待核实项**  
   单一来源、转述、年份过旧或互相冲突的信息。
7. **来源清单**  
   按 A、B、C、D 分组列出平台、标题或描述、日期、岗位关系和可点击链接。

不得伪造问题出现频次、帖子、作者、日期或链接。没有搜到直接面经时，明确写出检索范围和结果，再使用相近岗位信息补充，并始终标明降级。

## 完成前检查

- 确认已完整读取目标 JD，并正确提取公司和岗位关键词。
- 确认优先检索了公司 + 精确岗位，而非直接使用泛岗位题库。
- 确认利用了可访问的已打开/已登录目标平台；访问受阻时已如实说明。
- 确认所有高频结论来自多个独立来源。
- 确认相同考察点的不同问法已合并，正文没有重复问题。
- 确认问题顺序反映可信度和直接相关度。
- 确认结论置于文档最前，并说明证据强弱。
- 确认额外有价值的信息已整理，事实与推断已区分。
- 确认来源链接、日期和岗位关系可追溯。
- 确认输出文件位于目标公司文件夹且可正常打开。
