# 岗位分析与匹配

## 目标

基于岗位 JD、可靠的公开信息和共享事实库，形成可追溯的岗位理解与个人匹配结论。只使用有证据支持的个人事实，不补写或美化不存在的经历。

## 工作流

### 1. 确定任务范围

1. 从主控聊天命令中取得公司文件夹、岗位名称及用户指定的输出格式或文件名。
2. 将项目根目录视为包含 `共享事实库.docx` 和公司文件夹的目录。
3. 如果公司文件夹或目标岗位无法唯一确定，停止并向用户确认，不根据相似文件夹猜测。
4. 检查公司文件夹内的 JD 文件。优先读取用户点名的文件；否则读取文件名包含 `JD`、`岗位` 或目标岗位名称的 DOCX、PDF、Markdown 或文本文件。
5. 如果存在多个可能对应不同岗位的 JD 且无法唯一判断，向用户确认。

### 2. 读取本地依据

1. 完整读取目标岗位 JD，保留原始职责、任职要求、业务方向和关键词。
2. 完整读取项目根目录的 `共享事实库.docx`。
3. 需要处理 DOCX 或 PDF 时，调用相应文档或 PDF 能力，并遵循其读取和验证要求。
4. 可读取公司文件夹中的定制简历作为补充证据，但不得用它替代共享事实库。只有主控命令明确要求或文件能被唯一识别时才读取。
5. 建立内部证据表，记录每项结论的来源：JD 原文、本地事实库位置或网页链接。

### 3. 联网研究公司与岗位

1. 必须联网核验公司当前主要业务、产品或服务、客户与市场、岗位所属业务线，以及会影响岗位理解的近期公开信息。
2. 优先使用公司官网、官方招聘页、官方公告、年报或监管披露；必要时使用可靠行业媒体和主流招聘平台作为补充。
3. 搜索具体公司与具体岗位或同类岗位，不用泛化的岗位百科替代目标岗位研究。
4. 对可能变化的信息标注资料发布日期或检索日期。关键结论尽量交叉核验。
5. 区分“来源明确的事实”和“基于 JD/公开信息的推断”。不得把推断写成公司已确认事实。
6. 在输出中保留可点击的来源链接；避免长段引用，使用归纳表述。

### 4. 拆解岗位

将岗位分析为以下层级：

1. **业务目标**：岗位最终为哪类业务结果负责。
2. **核心职责**：合并 JD 中语义重复的内容，按重要性排序。
3. **核心能力项**：每项使用可观察、可验证的能力名称，如数据分析、项目推进、用户洞察、跨部门协作或客户开发；避免“综合素质强”等空泛标签。
4. **能力证据**：说明 JD 哪些措辞或业务背景支持该能力判断。
5. **可能考察方式**：推断面试官可能通过哪些问题或案例检验该能力，并明确标注为推断。

判断优先级时综合考虑：JD 出现频率、职责位置、明确的硬性要求、与业务结果的距离，以及公司当前业务背景。

### 5. 匹配个人经历

1. 仅从共享事实库及已授权读取的简历中提取个人经历。
2. 针对每个核心能力项，给出：
   - 最匹配经历及具体证据；
   - 可量化结果；
   - 匹配程度：强、中、弱或缺口；
   - 面试中可主讲的角度；
   - 仍需用户补充或确认的信息。
3. 同一经历可支持多个能力，但必须分别解释关联，不能只重复经历标题。
4. 不将参与经历夸大为主导，不创造数字、职责、工具、客户、奖项或结果。
5. 事实库没有证据时明确写“事实库暂无证据”，并将其列为准备缺口。

### 6. 选择面试重点

按“岗位重要性 × 证据强度 × 经历差异化 × 可讲述性”选择 2–4 个主卖点。每个主卖点说明：

- 为什么对该岗位重要；
- 应使用哪段经历；
- 建议重点讲清的行动、难点和结果；
- 需要避免的夸大或薄弱环节。

同时列出不应作为主线、但可以用于补充回答的经历，避免平均分配篇幅。

## 输出规范

若用户未指定格式，在目标公司文件夹中生成 `岗位分析与经历匹配.md`。若用户指定 DOCX 或其他文件名，服从其要求；生成 DOCX 时必须完成渲染和视觉检查。

文档按以下结构输出：

1. **岗位与资料范围**：公司、岗位、读取的本地文件、研究日期。
2. **公司与业务理解**：主要业务、岗位所处业务场景、与岗位相关的近期背景。
3. **岗位职责拆解**：职责、业务目标、判断依据和优先级。
4. **核心能力模型**：能力项、JD/业务依据、优先级、可能考察方式。
5. **个人经历匹配矩阵**：能力项、匹配经历、事实证据、匹配程度、面试讲法、缺口。
6. **面试主线建议**：排序后的 2–4 个主卖点及选择理由。
7. **风险与待确认项**：证据不足、信息冲突、需要用户补充的事实。
8. **信息来源**：本地文件清单和网页链接，注明检索日期。

保持内容具体、可用于后续自我介绍和问答生成。不要在本阶段代写完整自我介绍或整套面试回答。

## 完成前检查

- 确认目标公司和岗位唯一明确。
- 确认已读取完整 JD 和 `共享事实库.docx`。
- 确认公司业务和岗位背景经过联网核验。
- 确认个人经历、数字和成果均能追溯到本地证据。
- 确认事实与推断已明确区分。
- 确认能力项与经历逐项对应，而非泛泛总结。
- 确认主卖点有明确排序和选择理由。
- 确认输出文件位于目标公司文件夹且可正常打开。
