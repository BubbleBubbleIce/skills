# 写作风格指南

## 基本风格

- 默认中文。
- 使用技术复盘语气,不要写成宣传稿。
- 保持"业务问题 -> 技术机制 -> 工程收益"的因果链。
- 多用项目真实名词:模块名、接口名、配置管理、线程池、缓存、策略类、Advisor、Sink、规则表达式等。
- 少用泛词:"提升效率"、"优化体验"、"增强稳定性"必须落到具体机制上。
- 如果用户提供已有优秀参考产出,优先对齐其章节命名、标题颗粒度、技术复盘语气和"项目定位 -> 核心亮点 -> 技术深挖 -> 简历段落 -> 待补充信息 -> 面试话术 -> 项目意义"的展开节奏。

## 亮点写法

每个亮点使用三段式:

1. **问题背景**:为什么这个点值得做。写复杂度、风险、性能瓶颈、维护成本、业务约束。
2. **技术方案**:写具体机制。优先列代码结构、框架能力、线程模型、缓存策略、降级策略、配置模型。
3. **收益**:写结果。可以是可维护性、可扩展性、稳定性、可观测性、成本控制、关键流程保护。

示例句式:

- "如果把所有逻辑塞进一个 Service,后续新增场景会导致主流水线膨胀。"
- "将外部可变逻辑隔离到独立线程池,避免污染主业务线程。"
- "新增场景只需要新增策略类,主流程无需改动。"
- "失败统一降级为未命中,不影响关键流程。"

## 简历 bullet 风格

- 每条用一个黑体亮点开头。
- 后面紧跟机制,不要先写口号。
- 一条 bullet 只讲一个核心机制。
- 控制在 2-4 行,避免把面试深挖内容塞进简历。
- 对复杂项目可在简历段落前写一句"按粒子式风格整理,每条突出一个工程亮点",但不要让这句话替代真正的 bullet 质量。

好:

```markdown
- **500ms 超时熔断保护关键流程**:规则执行通过 `Future.get(500ms)` 设置硬上限,超时、异常统一按规则未命中处理,避免动态表达式拖慢核心请求流程。
```

差:

```markdown
- 负责规则引擎开发,提高了系统稳定性和可维护性。
```

## 面试话术风格

- 30 秒介绍要说清楚:业务场景、你的模块、技术难点、核心机制。
- 深挖引导要按面试官可能问的方向组织,例如业务价值、架构设计、并发、缓存、降级、扩展性、安全。
- 避坑提醒要主动压住不可证实的表述,尤其是"独立完成"、"主导上线"、"性能提升 X%"。

## 用词边界

| 风险词 | 更稳妥表述 |
| --- | --- |
| 独立完成整个系统 | 参与/负责核心模块/负责其中某条链路 |
| 主导上线 | 参与开发并完成联调/支持上线 |
| 通用平台 | 面向某业务场景的能力/规则引擎/工具 |
| 大幅提升性能 | 通过机制降低请求期成本/控制耗时上限 |
| 熟练掌握某框架 | 基于某框架扩展了某能力 |

## 标点和格式

- 与参考文档保持一致,英文逗号可写作半角`,`。
- 技术名词和代码标识用反引号。
- 每个大章节之间用 `---` 分隔。
- 表格只用于待补充信息或对照关系。
