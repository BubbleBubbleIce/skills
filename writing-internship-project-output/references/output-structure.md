# 输出结构模板

生成完整实习项目产出文档时,默认使用以下结构。若用户明确要求简化,可以只输出项目定位、核心亮点和简历段落。

## 标准章节

```markdown
# 实习项目产出 · <项目短名>

> 用于简历项目经历与面试话术整理。基于 `<项目/模块名>` 的实际代码或文档,提炼成可对外表述的技术产出。

---

## 一、项目定位

**项目名**:<项目名> - <一句技术定位>

**一句话概括**:
<用一段话说明做了什么、基于什么技术、解决什么问题、服务什么场景。>

**技术栈**:
<语言、框架、中间件、系统组件、关键技术>

**需求背景**:
<说明真实业务问题。重点写为什么需要这个项目,旧方案有什么痛点,这个项目在业务链路中的位置。>

---

## 二、核心亮点(4-5 条)

### 亮点 1 · <机制名或架构名>

**问题背景**:
<具体痛点。不要泛泛写"为了提高效率",要说明具体风险、复杂度或维护成本。>

**技术方案**:
- <机制 1>
- <机制 2>
- <机制 3>

**收益**:
- <工程收益>
- <业务收益>
- <可维护性或稳定性收益>

---

## 三、技术深度储备(面试深挖备用)

以下不一定全部写进简历,但面试官深挖时可以展开。

### Q1:<追问问题>
<回答。>

---

## 四、简历段落草稿

### <项目名>

**技术栈**:<技术栈压缩版>

**项目细节**:

- **<亮点标题>**:<机制 + 结果,控制在 2-4 行。>

---

## 五、待补充信息(整理最终版前建议确认)

| 项 | 建议补充 |
| --- | --- |
| 经历背景 | <准确对外口径> |
| 实习时间段 | <起止年月> |
| 个人角色 | <主导/参与/负责模块> |
| 业务范围 | <覆盖场景、上游、用户> |
| 可量化指标 | <只写有证据的指标> |
| 上线状态 | <开发/测试/预发/灰度/生产> |

---

## 六、面试话术要点

**电梯自我介绍(30 秒版)**:
> <一段 3-5 句的项目介绍。>

**深挖引导**:
- 面试官问 <方向> -> 引到 <可讲机制>

**避坑提醒**:
- <不要夸大的点>
- <需要保守表述的点>

---

## 七、项目意义总结

<用 3-5 条总结项目对开发者、维护者、使用者或团队的价值。不要写空泛口号,要回到复用性、可维护性、稳定性、质量保障、上下文控制、成本控制等工程收益。>
```

## 亮点数量选择

- 小项目:3 条亮点即可,每条写深。
- 中等项目:4 条亮点最稳。
- 系统性项目:5 条亮点,但每条必须有不同技术机制。
- 不要为了凑数把普通 CRUD、字段映射、接口联调写成亮点。

## 章节取舍

- 用户只要简历:输出"项目定位 + 简历段落草稿 + 待补充信息"。
- 用户要面试准备:保留"技术深度储备"和"面试话术要点"。
- 用户要沉淀完整产出:输出全部章节。
- 项目偏基础设施、工具链、Skill 或 Agent 工程化时,建议保留"项目意义总结",用于说明团队沉淀和复用价值。
